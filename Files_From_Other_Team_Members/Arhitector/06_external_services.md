# Интеграция с внешними сервисами (эмуляция) — кейс 2

Вызовы БКИ и СМЭВ выполняются локальными функциями-эмуляторами через `call_external()`. HTTP-запросы `POST /bki/score` и `POST /smev/identity` в CLI-прототипе не отправляются; приведённые JSON описывают входные данные и результаты эмуляторов.

## 1. БКИ (Бюро кредитных историй)

**Назначение:** получить кредитный score, флаг просрочки и число запросов за 90 дней.

**Входные данные эмулятора:**

```json
{
  "passport_hash": "a1b2c3d4e5f6a7b8"
}
```

В `04_прототип.py` функция `bki_emulator(passport_hash)` получает значение `passport_hash` из заявки. Отдельный HTTP-запрос не выполняется.

**Контракт ответа (успех):**

```json
{
  "score": 720,
  "delinquency": false,
  "requests_90d": 1
}
```

**Правила эмуляции (детерминизм):**

* Вызвать `md5_mod_10(passport_hash)`: `int(hashlib.md5(str(passport_hash).encode("utf-8")).hexdigest(), 16) % 10`.
* Если `h <= 5` → `score = 600 + h*20`, `delinquency = false`.
* Если `6 <= h <= 8` → `score = 450 + (h-6)*50`, `delinquency = false`.
* Если `h == 9` → `score = 400`, `delinquency = true`.
* `requests_90d = 1` (фиксировано).

**Таймаут:** 3 секунды на попытку; допускается до 2 попыток с паузой 0.5 секунды между ними.

## 2. СМЭВ (Система межведомственного электронного взаимодействия)

**Назначение в учебном эмуляторе:** детерминированно получить статус `MATCH` или `MISMATCH` на основе `client_id`. Текущая функция не получает `passport_hash` и не проверяет реальную связь паспортных данных с клиентом; это имитация результата проверки, а не полноценная проверка идентичности.

**Входные данные эмулятора:**

```json
{
  "client_id": "cli_0001"
}
```

В `04_прототип.py` функция `smev_emulator(client_id)` получает только `client_id`. `passport_hash` в функцию СМЭВ не передаётся; отдельный HTTP-запрос не выполняется.

**Контракт ответа (успех):**

```json
{
  "status": "MATCH"
}
```

`status` — enum: `MATCH`, `MISMATCH`, `TIMEOUT`, `NOT_CALLED`.

**Правила эмуляции (детерминизм):**

* Вызвать `md5_mod_10(client_id)`: `int(hashlib.md5(str(client_id).encode("utf-8")).hexdigest(), 16) % 10`.
* Если `h == 0` → `status = MISMATCH`.
* Иначе (`1 <= h <= 9`) → `status = MATCH`.
* В режиме `emulator` функция возвращает только `MATCH` или `MISMATCH`. В режиме `csv` код всё равно вызывает обёртку `call_external()`, а сама функция возвращает `app["smev_status"]` или `NOT_CALLED`, если поле пустое. Поэтому такой `NOT_CALLED` записывается в `external.log` как `SUCCESS` с `result: {"status":"NOT_CALLED"}`; это не означает отсутствие вызова обёртки. Если конвейер завершился раньше этапа СМЭВ, вызова СМЭВ нет вообще и отдельная запись `NOT_CALLED` не создаётся. В `decide()` статус `NOT_CALLED` приводит к `NEED_MORE_DATA / EXTERNAL_TIMEOUT`.

**Таймаут:** 3 секунды на попытку; допускается до 2 попыток с паузой 0.5 секунды между ними.

## 3. Фактический порядок вызовов и принятия решения

По актуальному `04_прототип.py` порядок для каждой заявки следующий:

1. `validate(app)`: проверяются возраст, занятость, доход, сумма, срок, `family`, `app_id`, `client_id` и формат `passport_hash`. При ошибке заявка завершается до внешних вызовов.
2. `select_product(app, products)`: подбирается продукт по ID (если задан), возрасту, сумме, сроку и минимальному доходу. Если продукт не выбран, формируется `REFUSED` с `LOW_INCOME` или `PRODUCT_NOT_AVAILABLE`; внешние сервисы не вызываются.
3. Рассчитывается точный DTI по ставке выбранного продукта. Если `exact_dti > 0.5`, формируется `REFUSED / HIGH_DTI`; БКИ и СМЭВ не вызываются.
4. В режиме `csv` проверяется входной `bki_score`/`delinquency`. При ошибке формируется `NEED_MORE_DATA` (`MISSING_BKI` или `VALIDATION_ERROR`) без вызова БКИ.
5. Вызывается БКИ через `call_external()`: в `csv` режиме используется `csv_bki_value()`, в `emulator` — `bki_emulator(passport_hash)`. При отсутствии результата — `NEED_MORE_DATA / EXTERNAL_TIMEOUT`. Диапазон BKI score дополнительно проверяется: 300–850.
6. По успешному ответу БКИ рассчитывается score. В текущем коде score включает компоненты `income`, `employment`, `age`, `family` и `bki`.
7. Перед СМЭВ вызывается `decide(..., smev="MATCH", ...)` как предварительная проверка. Если причина — `BKI_DELINQUENCY`, `AMOUNT_LIMIT` или `LOW_SCORE`, обработка завершается и СМЭВ не вызывается.
8. Иначе вызывается СМЭВ через `call_external()`: в `emulator` — `smev_emulator(client_id)`, в `csv` — значение `smev_status` из заявки или `NOT_CALLED` при пустом поле.
9. После СМЭВ `decide()` формирует итог: `MISMATCH` → `REFUSED / SMEV_MISMATCH`; `MATCH` при прохождении остальных проверок → `APPROVED`; `TIMEOUT` или `NOT_CALLED` → `NEED_MORE_DATA / EXTERNAL_TIMEOUT`.

Следовательно, фактическая последовательность — БКИ → скоринговые/стоп-проверки → СМЭВ. СМЭВ не вызывается, если заявка завершилась на любом из ранних этапов.

## 4. Поведение при таймауте и ошибке

* Лимит одной попытки — 3 секунды.
* При `TIMEOUT` выполняется одна повторная попытка после паузы 0.5 секунды.
* Если обе попытки завершились `TIMEOUT`, сервис считается недоступным; решение конвейера — `NEED_MORE_DATA`, reason — `EXTERNAL_TIMEOUT`.
* При исключении (`ERROR`) текущая реализация не делает повтор: фиксирует `ERROR` и завершает вызов. Для конвейера отсутствие ответа также приводит к `NEED_MORE_DATA / EXTERNAL_TIMEOUT`.
* Таймаут/ошибка не трактуются как отказ (`REFUSED`).
* Клиенту показывается сообщение из каталога причин: «Не хватает результата внешней проверки: сервис не ответил. Повторите попытку позже».

**Максимальное время:** до 13 секунд возможно, если первый вызов БКИ завершается `TIMEOUT`, повторный вызов БКИ успешно завершается только после ожидания до 3 секунд, а затем обе попытки СМЭВ завершаются `TIMEOUT`: БКИ до 6.5 секунды (3 + 0.5 + 3) и СМЭВ до 6.5 секунды (3 + 0.5 + 3). Если обе попытки БКИ завершаются таймаутом, СМЭВ уже не вызывается. Это превышает NFR-2 «полное время решения ≤ 10 с (p95)». В актуальном отчёте QA также отмечено, что на тестовых данных таймауты фактически не возникали; отсутствие таймаутов в этих прогонах не снимает расхождение с бюджетом NFR-2.

## 5. Журналирование вызовов (`external.log`)

Каждая фактическая попытка внешнего вызова записывается отдельной JSONL-строкой. По текущему коду в запись входят:

| Поле | Пример / содержание | Назначение |
|---|---|---|
| `timestamp` | ISO timestamp | Время вызова |
| `run_id` | идентификатор запуска | Связать записи одного прогона |
| `service` | `BKI` / `SMEV` | Внешний сервис |
| `app_id` | `app_0001` | Заявка |
| `request_id` | первые 8 символов `run_id`, индекс заявки с дополнением нулями до 4 знаков и сервис, например `a1b2c3d4-0001-BKI` | Идентификатор конкретного вызова |
| `attempt` | `1` или `2` | Номер попытки |
| `status` | `SUCCESS` / `TIMEOUT` / `ERROR` | Итог попытки |
| `latency_ms` | например `120` | Фактическая задержка |
| `result` | успешное тело ответа; `{}` при `TIMEOUT`/`ERROR` | Результат вызова |
| `error_type` | тип исключения или пустая строка | Диагностика сбоя |

`passport_hash` в объект записи `external.log` не включён: в журнал передаются только перечисленные ниже поля. Вызовы выполняются локально, а не по сети.

Пример успешной записи:

```json
{
  "timestamp": "2026-11-09T10:00:00Z",
  "run_id": "a1b2c3d4e5f678901234567890123456",
  "app_id": "app_0001",
  "service": "BKI",
  "request_id": "a1b2c3d4-0001-BKI",
  "attempt": 1,
  "status": "SUCCESS",
  "latency_ms": 120,
  "result": {"score": 720, "delinquency": false, "requests_90d": 1},
  "error_type": ""
}
```

## 6. Ограничения и открытые расхождения

1. В `02_правила_заполненная.md` и `08_reasons.md` указан другой порядок внешних проверок, чем в текущем коде и QA-отчёте.
2. NFR-2 ограничивает полное время решения 10 секундами (p95), тогда как худший последовательный сценарий двух внешних сервисов достигает 13 секунд.
3. СМЭВ-эмулятор принимает только `client_id`; он не получает и не сопоставляет `passport_hash`. Поэтому описание СМЭВ как реальной проверки связи паспорта и клиента не соответствует текущему коду.
4. Формат `passport_hash` в материалах описан неодинаково: требования и словарь фиксируют 16 hex-символов, API-образец также фиксирует 16 символов в нижнем регистре, а `validate()` и `save_client()` в прототипе принимают 16 или 64 hex-символа в обоих регистрах.
5. В режиме `csv` СМЭВ-обёртка вызывается даже при пустом `smev_status`; в лог попадает успешный вызов с результатом `NOT_CALLED`. При раннем завершении до этапа СМЭВ записи о вызове нет.
6. Вызовы БКИ/СМЭВ в текущем CLI — локальные функции, не реальные HTTP-интеграции.
