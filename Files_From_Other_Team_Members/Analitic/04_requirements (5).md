# Требования — кейс 2 «Кредитный конвейер»

Сервис принимает кредитную заявку, подбирает кредитный продукт, проверяет заявку по внутренним правилам, кредитной истории (БКИ) и госреестрам (СМЭВ) и возвращает предварительное решение с объяснимой причиной.

Колонка «Прототип» показывает, что реализовано в 04_прототип.py.

## Функциональные требования

| ID | Требование | Приоритет | Прототип | Тест |
| - | - | - | - | - |
| FR-1 | Принять кредитную заявку по app_id, client_id, passport_hash, age, income, employment, family, amount, term | Must | Реализовано | T2-1: корректная заявка → строка в decisions.csv и Decision.csv, клиент в Client.csv |
| FR-2 | Валидировать заявку: обязательные поля, типы, справочники employment/family, age 18–70, income > 0, amount 10 000–5 000 000, term 3–60, passport_hash 16 hex | Must | Реализовано | T2-2: пустой income → NEED_MORE_DATA / MISSING_INCOME; age 17 → AGE_OUT_OF_RANGE; passport_hash из 10 символов → VALIDATION_ERROR |
| FR-3 | Подобрать продукт из products.csv по возрасту, доходу, сумме и сроку. Из подходящих выбрать продукт с минимальной ставкой | Must | Реализовано | T2-3: доход 15 000, 19 лет → Студенческий; нет подходящего продукта → PRODUCT_NOT_AVAILABLE |
| FR-4 | Запросить кредитную историю в БКИ по passport_hash и получить bki_score 300–850 и признак просрочки | Must | Реализовано | T2-4: score 499 → BKI_DELINQUENCY, score 500 → проверка пройдена |

| FR-6 | Рассчитать dti = аннуитетный платёж / income по ставке продукта и отказать при dti > 0.5 | Must | Реализовано | T2-6: dti 0.50 → проходит, 0.51 → HIGH_DTI |
| FR-7 | Применить лимиты: минимальный доход продукта, amount ≤ 10 × income, unemployed → отказ | Must | Реализовано | T2-7: unemployed → INVALID_EMPLOYMENT; доход ниже минимума продукта → PRODUCT_MIN_INCOME; сумма > 10 × income → AMOUNT_LIMIT |
| FR-8 | Рассчитать скоринговый балл и отказать при score < 60 | Must | Реализовано | T2-8: все стоп-правила пройдены, score 55 → LOW_SCORE |

| FR-10 | Вернуть код причины из каталога и текст для клиента при любом решении, кроме APPROVED | Must | Реализовано | T2-10: для каждого reason выводится текст из REASON_MESSAGES |

| FR-12 | Предоставить эмуляторы БКИ и СМЭВ с настраиваемыми ответами, включая задержку и таймаут | Must | Частично: таймаут и повтор есть, задержку нельзя задать параметром запуска | T2-12: эмулятор с задержкой 5 с → NEED_MORE_DATA / EXTERNAL_TIMEOUT |

## Нефункциональные требования

| ID | Требование | Прототип |
| - | - | - |
| NFR-1 | Внешний запрос в БКИ и СМЭВ ≤ 3 с, при таймауте 1 повтор через 0.5 с | Реализовано |
| NFR-2 | При таймауте БКИ или СМЭВ заявка получает NEED_MORE_DATA / EXTERNAL_TIMEOUT, а не отказ. Полное время решения ≤ 10 с (p95) | Частично: в худшем случае 2 сервиса × (3 + 0.5 + 3) с = 13 с. Нужно 1 попытка или таймаут 2 с |
| NFR-3 | Объяснимость: каждое решение, кроме APPROVED, содержит reason из каталога. Решение воспроизводимо по входным данным и версии правил | Частично: reason есть всегда, версии правил нет |
| NFR-4 | Маскирование: паспорт хранится только как хэш (рекомендуется HMAC-SHA-256), в логах персональные данные замаскированы. Соответствие 152-ФЗ | Частично: прототип принимает готовый 16-hex хэш, HMAC не реализован; age и income хранятся в Client.csv открыто |
| NFR-5 | Отсутствие дискриминации: запрещено использовать пол, национальность, религию и семейное положение. Возраст используется в скоринге по условию кейса и как ограничение продукта | Не выполнено: family даёт 15 / 15 / 10 баллов (см. 02_правила) |
| NFR-6 | Аудит: журнал решений неизменяем (append-only) и хранит каждое решение с версией правил | Частично: decision_audit.log и AuditEvent.csv только дописываются, версии правил нет |

## Ограничения

- Реальные БКИ и СМЭВ не подключаются. Используются эмуляторы с тем же контрактом или значения из applications.csv (режим `--external-source csv`).

- Все данные синтетические: 100 заявок в applications.csv, хэши паспортов не соответствуют реальным людям.

- Решение только предварительное. Финальное решение принимает банк после проверки документов.

- Ставка (12–22% годовых), минимальный доход, диапазоны возраста, суммы и срока задаются в products.csv. Лимит 10 × income пока зашит в коде.

## Пользовательские сценарии

### Сценарий 1. Клиент подал заявку и получил одобрение

1. Клиент заполняет анкету: возраст, ежемесячный доход, занятость, семейное положение, сумму и срок кредита.

2. Клиент даёт согласие на запрос кредитной истории и проверку паспортных данных.

3. Через несколько секунд клиент видит предварительное одобрение, подобранный продукт и ставку.

4. Клиент получает сообщение, что для финального решения банк может запросить документы, и список следующих шагов.

### Сценарий 2. Клиент получил отказ

1. Клиент запрашивает 800 000 ₽ на 24 месяца при доходе 60 000 ₽ в месяц.

2. Конвейер подбирает Потребительский стандарт (18%) и считает dti = 0.67.

3. Клиент видит предварительный отказ с причиной: «Отказ: долговая нагрузка (DTI) превышает допустимые 50% дохода».

4. Клиент меняет параметры заявки и подаёт её повторно.

### Сценарий 3. Проверку не удалось завершить

1. Клиент подаёт заявку, но сервис проверки данных не отвечает и после повторной попытки.

2. Клиент видит сообщение «Не хватает результата внешней проверки: сервис не ответил. Повторите попытку позже». Отказа нет.

3. Клиент повторяет попытку позже, и заявка рассматривается заново.
